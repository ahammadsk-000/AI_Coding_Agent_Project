1The 30-second pitch

A self-hostable agentic RAG platform over your codebase: point it at a git repo, and it clones + indexes the code with tree-sitter + embeddings, then lets you search (hybrid retrieval), chat (RAG + tool-using agent), run a multi-agent research/audit pipeline, and open GitHub PRs. Async FastAPI + SQLAlchemy 2.0 backend, React/Vite frontend, Postgres + Qdrant + Redis, with pluggable LLM (Ollama/OpenAI/Groq) and embeddings (local/Jina/OpenAI). Clean Architecture + DDD; the agent loop, hybrid-search fusion, and provider abstractions are hand-written (no LangChain).
What I built vs. glued: hand-wrote the agent loop, tool dispatch, RRF fusion, AST-aware chunker, multi-agent pipeline + critic/Reflexion, RAG-eval harness, MCP server, and provider abstractions. Glued in Postgres/Qdrant/Redis and the LLM/embedding HTTP APIs.

4The 5 flows to narrate

A. Ingestion: POST /repositories/{id}/ingest → create job → clone (shallow, capped) → tree-sitter parse + symbols → AST-aware chunking (tiktoken budget) → embed (batched) → upsert to Qdrant (1 collection/repo) → store in Postgres → publish progress to Redis → SSE to UI → status ready.
B. Search/RAG: embed query → Qdrant kNN (dense) in parallel with Postgres ts_rank_cd (sparse) → RRF fuse (k=60) → optional cross-encoder rerank → filter padding → top-k.
C. Chat: WS → persist message → (skip if chit-chat) hybrid search → system prompt with repo inventory + RAG context (~1500 tok) + memories → stream LLM → execute tool calls (deduped, capped 2/round & 3/turn) → loop ≤5 → stream tokens + citations.
D. Multi-agent: Planner → per-sub-question Researchers (grounded) → Synthesizer → Critic (verdict) → Reflexion revises once on "issues" → re-review. Each stage an SSE event.
E. RAG eval: run real retrieval + grounded generation → LLM-as-judge scores faithfulness / answer-relevance / context-precision. Reference-free.

7Q&A — the opener

Tell me about your project.

See the 30-second pitch above. Structure: what it is (agentic RAG over your code) → the flows (ingest, search, chat, multi-agent, PRs) → the stack (FastAPI async, Postgres/Qdrant/Redis, pluggable LLM) → what I built myself (agent loop, RRF, chunker, multi-agent, provider abstractions).

What did you build vs. glue together?

Hand-wrote the agent loop, tool dispatch, hybrid-search fusion (RRF), AST-aware chunker, the multi-agent pipeline with critic/Reflexion, the RAG-eval harness, the MCP server, and the LLM/embedding provider abstractions. Glued in Postgres/Qdrant/Redis and the LLM/embedding HTTP APIs. I deliberately avoided LangChain/CrewAI so I understand the mechanics.

8Q&A — architecture & design

Why Clean Architecture + DDD here?

Testability and swappability. Each bounded context has models/repository/schemas/service; external systems live behind Protocols in infrastructure. I can swap an LLM provider or the vector DB without touching business logic, and unit-test services with fakes.

How do the three data stores divide responsibility?

Postgres = system of record + sparse/full-text search. Qdrant = dense vectors (ANN). Redis = ephemeral: cache, rate-limit counters, Celery broker, pub/sub for progress. Truth is never stored in Redis.

How would you scale to 10× users? senior

API is stateless → horizontal scale behind a load balancer (Helm HPA already). Move ingestion fully onto Celery and scale that pool independently. Bottlenecks are LLM/embedding rate limits and ingestion memory → batch embeddings, retry with backoff, per-repo Qdrant collections, token-budgeted context. Next lever: semantic caching of embeddings/searches.

9Q&A — RAG & retrieval

Why hybrid search instead of pure vector search?

Dense captures semantics ("auth flow") but misses exact identifiers (RefreshToken); BM25/full-text nails exact tokens but misses paraphrase. Code search needs both, so I run them in parallel and fuse.

What is Reciprocal Rank Fusion and why over score-weighting? senior

RRF scores each doc as Σ 1/(k + rank) across ranked lists (k=60). It fuses on rank, not raw scores, so I don't normalize incomparable cosine vs ts_rank_cd scales. Robust and parameter-light.

What's your chunking strategy and why does it matter? senior

AST-aware chunking with tree-sitter: chunk on symbol boundaries (functions/classes) so a chunk is a semantically whole unit; split oversized symbols by a token-budgeted line window; gap-fill between symbols. Naive fixed-size chunking splits functions mid-body and wrecks retrieval + grounding.

What's re-ranking and when is it worth it?

After fusion I optionally run a cross-encoder that jointly encodes (query, chunk) for a precise relevance score, then reorder. It's slow (uncacheable, per-candidate) so I apply it to a small top-N pool, not the corpus.

RAG vs fine-tuning vs long-context — when each? senior

RAG for knowledge that changes / is large / proprietary (my case). Fine-tuning to change behavior/format/style, not for facts. Long-context when the whole relevant corpus fits and recall beats cost. They compose.

How do you keep the prompt from overflowing the context window?

pack_context groups hits by file, merges overlapping/adjacent line ranges, and greedily packs under a ~1500-token budget via tiktoken. The context window is a budget you architect.

10Q&A — embeddings & vector search

What are embeddings and how do you measure similarity?

Embeddings map text to vectors where distance ≈ semantic similarity. I use cosine similarity (Qdrant, normalized vectors) — angle, ignoring magnitude.

How does ANN work / why Qdrant? senior

Exact kNN is O(N·d) per query — too slow at scale. Qdrant uses HNSW, a navigable small-world graph giving approximate nearest neighbors in ~log time, trading a little recall for big speed. One collection per repo, cosine distance, payload indexes for filtering.

You switched embedding providers in prod — what broke? senior

Embedding dimension and semantics are provider-specific — vectors aren't comparable across models, so switching means the collection dimension must match; I re-ingest. Also hit 429s on the hosted API → added retry-with-backoff and batching.

11Q&A — LLM integration & the chat agent

How is the app model-agnostic?

An LLMProvider Protocol (chat, stream, tool support) + a factory that returns Ollama/OpenAI/Groq from config — even per-conversation. Everything depends on the Protocol, not a concrete SDK.

How does streaming tool-calling actually work? senior

I stream the completion; text deltas go to the user, tool-call fragments are reassembled (OpenAI streams arguments in pieces). When the model finishes with tool_calls, I execute, append tool-result messages, and call again — the ReAct loop. No tool calls → done.

Same prompt, different answers — why? How do you make judges reproducible?

Sampling (temperature/top_p); even at temp 0, server-side batching/float gives slight nondeterminism. For critic/judge calls I use temperature 0 to minimize variance.

How does the agent decide to stop?

When the LLM returns no tool_calls, the loop ends. Hard cap at 5 rounds as a backstop.

A model spammed a tool in a loop and blew the token budget — fix? senior

Real bug I fixed. Now I de-dup identical tool calls, cap execution to 2/round & 3/turn then force a prose answer, cap each tool result to ~3000 chars, and treat rate-limit/413 as terminal with a friendly message. A tool_use_failed retries once without tools. Guardrails against runaway agents are a real production concern.

How do you prevent hallucinated file paths / fake code?

System prompt forbids inventing paths and requires citing exact file:line from retrieved context; I preload the repo file inventory so it uses real names; and I detect "leaked" tool-call text. Grounding + citations make answers verifiable.

12Q&A — agentic AI

Difference between a workflow and an agent? senior

A workflow has fixed, developer-defined control flow; an agent lets the LLM decide the next step. My chat is an agent (LLM-driven loop); my multi-agent pipeline is a structured orchestration — deterministic stages, each powered by an LLM.

Explain your multi-agent pipeline and why a critic.

Planner → per-sub-question Researchers (grounded) → Synthesizer → Critic that fact-checks the answer against the researchers' findings and returns accurate/issues/uncertain. A single pass can be confidently wrong; an independent critic catches unsupported claims.

What is Reflexion and how did you implement it? senior

Self-correction from feedback: if the critic returns issues, feed its critique back to the synthesizer to revise once, then re-review. Bounded (one iteration) so it can't spin forever.

ReAct — what is it?

Reason + Act: the model interleaves reasoning with tool actions and observations. My chat loop is exactly this — think, call a tool, read the result, continue.

13Q&A — evaluation & MCP

How do you know your RAG is any good? senior

A RAG-eval harness (LLM-as-judge) scoring faithfulness (grounded?), answer relevance, and context precision — the RAGAS triad, reference-free (no labels). It runs the real pipeline, catching retrieval and generation regressions.

Weakness of LLM-as-judge and how do you mitigate it?

Judges are biased/noisy (verbosity, position, self-preference). Mitigate with temperature 0, focused single-metric prompts, and a forced SCORE: format I parse. For rigor, add human-labeled goldens and correlate.

What is MCP and what did you build? senior

MCP is an open standard letting any AI host (Claude Desktop, IDEs) connect to tools/data uniformly — "USB-C for AI tools." I built a FastMCP server exposing search_code/read_file/list_repositories over stdio; a thin client on my REST API, so Claude Desktop can search my indexed repos.

14Q&A — streaming, data & security

Why WebSocket for chat but SSE for ingestion/agents? senior

Chat is bidirectional/interactive (send, stream tokens, stop) → WebSocket. Ingest/agents/audit are server→client only → SSE (simpler, plain HTTP, auto-reconnect). I use a fetch-based SSE reader so I can send the Authorization header (browser EventSource can't).

A gotcha you hit with SSE? senior

SSE showed nothing. Two causes: (1) the endpoint used the request-scoped DB session, torn down before the stream body runs → I open a fresh session inside the generator; (2) my parser split on \n\n but the server emitted \r\n\r\n → I normalize CRLF.

Why async SQLAlchemy 2.0?

Workload is I/O-bound (DB + LLM + vector calls); async handles many concurrent requests without thread-per-request overhead. Typed Mapped[...] models are clean and mypy-friendly.

How does Postgres full-text search work here?

A generated STORED content_tsv column with a GIN index on code_chunks; queries use plainto_tsquery + ts_rank_cd. plainto_tsquery is forgiving of raw user text.

A production DB gotcha you solved? senior

On Neon, asyncpg rejects the sslmode query param libpq uses — I strip sslmode/channel_binding and pass ssl=require via connect_args.

Explain your auth & how the sandbox is hardened.

Argon2id hashing; short-lived JWT access + opaque refresh tokens with single-use rotation; RBAC guards; frontend refreshes once on 401. Sandbox: disposable Docker with network_mode=none, cap_drop=ALL, no-new-privileges, read-only root + tmpfs, non-root, memory/CPU/pids caps, hard timeout, plus a command-policy classifier. Disabled on managed cloud (no Docker socket) behind a flag.

Prompt injection — do you handle it?

Mitigations: read-only tools, grounding + citation requirements, chit-chat/leaked-tool-call detection, never executing model output directly (writes gated). Fuller answer: treat retrieved content as untrusted, separate instructions from data, validate outputs.

15Q&A — deployment & ops

How is it deployed & what did you trade off on free tier? senior

Three ways: docker-compose (9 services) local, Helm (HPA/PDB/NetworkPolicy) for K8s, and a free-tier split (Render/Vercel/Neon/Upstash/Qdrant/Groq/Jina). Trade-offs: no Celery worker → inline subprocess ingestion; no Docker socket → sandbox off (flag); Groq's 6000 TPM free limit forced the tool-call/token caps. Graceful degradation, not feature removal.

How do you observe the system & track cost?

Prometheus metrics (aca_*: HTTP, LLM calls/tokens/latency, tools, search, ingest), structlog with a request_id per request, Grafana. Cost: core/cost.py counts tokens with tiktoken × a per-1M-token price table (local = free) → a Prometheus counter + an estimated-token meter on the Agents page.

Where does it break under load? senior

LLM/embedding rate limits first; then ingestion memory; then Postgres FTS on huge repos. Mitigations: batching, backoff, per-repo collections, token budgets. Retrieval quality is the whole game — my eval harness targets exactly that.

16Practical / hands-on questions

These are the "show me you can build it" questions — mini-coding, scenarios, and debugging grounded in this project.

Implement Reciprocal Rank Fusion for two ranked lists. practical
def rrf_fuse(rankings, k=60):
    scores, seen = {}, {}
    for ranking in rankings:              # each = ordered list of items
        for rank, item in enumerate(ranking):
            scores[item.id] = scores.get(item.id, 0) + 1 / (k + rank + 1)
            seen.setdefault(item.id, item)
    return sorted((seen[i] for i in scores),
                  key=lambda it: scores[it.id], reverse=True)

Key point: fuse on rank, not raw scores, so incomparable score scales don't need normalization.

Walk me through adding a new tool to the chat agent. practical

Three steps in chat/tools.py: (1) add a ToolDef with a JSON-schema (name, description, parameters); (2) write an async handler _handle_x(user, args, session) -> (result, summary, citations); (3) register it in the _HANDLERS dict. The agent loop picks it up automatically. Keep it read-only; coerce arg types defensively (models sometimes send numbers as strings — I use ["integer","string"] in the schema).

The SSE stream shows nothing. Debug it. practical

Checklist I actually used: (1) Is the endpoint using the request-scoped DB session? FastAPI tears it down before the streaming generator runs → open a fresh session_factory() session inside the generator. (2) Line-ending mismatch: parser splits on \n\n but sse_starlette emits \r\n\r\n → normalize CRLF. (3) Proxy buffering (disable with X-Accel-Buffering: no). (4) CORS/auth on the GET. (5) Is the generator actually yielding, or erroring before first yield?

Write a token-budgeted context packer. practical
def pack_context(hits, max_tokens, count):
    out, used = [], 0
    for h in hits:                        # already ranked best-first
        t = count(h.content)
        if used + t > max_tokens:
            break                         # greedy: stop at the budget
        out.append(h); used += t
    return out, used

Refinements in the real code: group by file and merge overlapping/adjacent line ranges before counting, so you don't waste budget on duplicate lines.

Retrieval returns irrelevant chunks on a small repo. Why, and fix? practical

On a tiny corpus, dense kNN always returns something even if cosine is low ("padding"). Fix: after fusion, drop hits that are dense-only and below a cosine floor (I use ~0.55), keep anything that also matched lexically or, if reranked, above the cross-encoder floor. That's the _filter_padding step.

Add caching to search — where and how? practical

Two layers: (1) embedding cache — hash the query text → cache the vector in Redis (embeddings are deterministic, huge win). (2) result cache — key on (normalized_query, repo_ids, mode, k) with a short TTL. Invalidation: bump a per-repo version on re-ingest and include it in the key, so a re-indexed repo misses stale results.

Scale ingestion for a 100k-file repo. practical

Stream, don't load: walk files lazily; filter by language/size/ignored dirs early; batch embeddings (256) and upserts; commit chunks in batches to bound memory; parallelize across files with a bounded worker pool; skip binaries/vendored dirs; cap per-file chunk count. Publish progress so it's observable. On the free tier, the inline subprocess gets its own engine/loop so it doesn't exhaust the API pool.

Write a judge prompt for faithfulness + parse it. practical
SYS = ("Judge FAITHFULNESS. Given CONTEXT and ANSWER, is every claim "
       "supported by the context? Reply exactly one line "
       "'SCORE: <0.0-1.0>' then one sentence of justification.")

import re
def parse_score(text):
    m = re.search(r"score\s*[:=]?\s*(\d(?:\.\d+)?)", text, re.I)
    return max(0.0, min(1.0, float(m.group(1)))) if m else 0.0

Use temperature 0. Forcing a machine-parseable SCORE: line is what makes LLM-as-judge usable programmatically.

How would you migrate embedding providers safely? practical

New provider = new dimension/semantics → old vectors are useless. Plan: (1) stand up the new provider behind the same Protocol; (2) create new Qdrant collections at the new dimension (don't mix); (3) re-embed + re-ingest per repo (background); (4) flip search to the new collections; (5) delete old. Blue/green by collection name avoids downtime.

Design per-user rate limiting with Redis. practical

Sliding-window counter keyed by (subject, route_group, window) where subject = user id (authed) or IP (anon). INCR the key, set a 60s TTL on first hit, reject when it exceeds the group's limit. Critically, fail open — if Redis is unreachable, allow the request (availability > a perfect limit for a non-critical control).

Add a new "Verifier" agent to the multi-agent pipeline. practical

In agents/service.py: add a _verify() method (an LLM call with its own system prompt + the synthesized answer), then insert it into both run() and run_stream() after the critic; in the streaming version yield ("verify", {...}) so the SSE frontend shows a new stage. Guard the call so a failure degrades to a partial result. The frontend just needs to handle the new event type.

Write the Postgres full-text query for code chunks. practical
SELECT cc.id, rf.path,
       ts_rank_cd(cc.content_tsv, plainto_tsquery('english', :q)) AS rank
FROM code_chunks cc
JOIN repository_files rf ON rf.id = cc.file_id
WHERE cc.repository_id = ANY(:repo_ids)
  AND cc.content_tsv @@ plainto_tsquery('english', :q)
ORDER BY rank DESC
LIMIT :k;

content_tsv is a generated STORED column with a GIN index; plainto_tsquery avoids syntax errors on raw user text.

Handle a 429 / rate limit from the LLM gracefully. practical

Distinguish error types: a tool_use_failed → retry once without tools. A rate-limit / request-too-large (413/429) → don't retry the same oversized request; surface a friendly message ("hit the free-tier token limit, try a shorter question or wait a minute"). Proactively, cap tool calls and tool-result sizes so a single request stays under the TPM ceiling. For embeddings, retry with exponential backoff.

Whiteboard: design this RAG system from scratch. practical senior

Two pipelines. Indexing (offline): ingest source → clean/split into semantically-whole chunks → embed → store vectors + metadata in a vector DB, and text in a store with full-text. Query (online): embed query → dense kNN + sparse search → fuse (RRF) → rerank top-N → pack under a token budget → prompt the LLM with context + citation instructions → stream. Cross-cutting: eval (faithfulness/relevance), caching, observability, guardrails, and provider abstraction. Say "retrieval quality is the whole game" and mention how you'd measure it.

Secure a new write endpoint. practical

Add the auth dependency (CurrentUser) so it requires a valid JWT; add an RBAC guard if it's privileged (require_role); validate/parse the body with a Pydantic schema (never trust raw input); enforce ownership in the service (the resource belongs to owner.id); rate-limit it; and if it triggers external side effects, make it idempotent or gated (like PR creation / the sandbox).

Extend the chunker to split an oversized function. practical
def chunk_symbol(sym, lines, max_tokens, count):
    body = "\n".join(lines[sym.start:sym.end])
    if count(body) <= max_tokens:
        yield Chunk(body, sym.start, sym.end)      # whole symbol — ideal
        return
    # too big: slide a line window that stays under the token budget
    start = sym.start
    while start < sym.end:
        end = start
        while end < sym.end and count("\n".join(lines[start:end + 1])) <= max_tokens:
            end += 1
        end = max(end, start + 1)                   # always make progress
        yield Chunk("\n".join(lines[start:end]), start, end)
        start = end

Principle: keep whole symbols when they fit (best for retrieval + grounding); only fall back to a token-budgeted line window when a single symbol exceeds the budget. For unsupported languages, skip AST and line-window the whole file.

Write the WebSocket chat handler (the transport layer). practical
@router.websocket("/{conv_id}/ws")
async def chat_ws(ws: WebSocket, conv_id: UUID, access_token: str):
    user = await authenticate(access_token)     # token via ?access_token= (WS can't set headers)
    await ws.accept()
    async with session_factory() as session:    # own session for the connection's lifetime
        service = ChatService(session)
        try:
            while True:
                frame = await ws.receive_json()
                async for event in service.send_message_streaming(
                    user, conv_id, frame["content"]
                ):
                    await ws.send_json(event.model_dump(mode="json"))  # WsToken/WsToolCall*/WsDone
        except WebSocketDisconnect:
            return

The router is thin: authenticate, accept, then loop — receive a frame, drive the streaming service, forward each Ws* event as JSON. Auth is via a query param because browsers can't set headers on a WebSocket handshake.

Implement single-use refresh-token rotation. practical
async def refresh(raw_token, repo):
    row = await repo.get_by_hash(sha256(raw_token))     # store hashes, never raw
    if row is None or row.revoked or row.expires_at < now():
        raise UnauthorizedError("invalid refresh token")
    await repo.revoke(row)                               # single-use: burn it
    new_raw = issue_opaque_token()
    await repo.add(hash=sha256(new_raw), user_id=row.user_id, expires_at=...)
    return new_access_jwt(row.user_id), new_raw

Refresh tokens are opaque + hashed at rest; each use is revoked and replaced. Detecting reuse of an already-revoked token is a signal to revoke the whole family (theft).

Retry-with-backoff for the embeddings API. practical
async def embed_batch(texts, tries=4):
    for attempt in range(tries):
        try:
            return await client.embed(texts)
        except httpx.HTTPStatusError as e:
            transient = e.response.status_code in (429, 500, 502, 503)
            if transient and attempt < tries - 1:
                await asyncio.sleep(2 ** attempt)   # 1s, 2s, 4s
                continue
            raise

Only retry transient statuses; exponential backoff avoids hammering a rate-limited provider. Real code also batches (≤256) so one 429 doesn't fail the whole ingest.

Cosine similarity from scratch (and why we normalize). practical
import math
def cosine(a, b):
    dot = sum(x * y for x, y in zip(a, b))
    na = math.sqrt(sum(x * x for x in a))
    nb = math.sqrt(sum(y * y for y in b))
    return dot / (na * nb) if na and nb else 0.0

If you normalize vectors to unit length at ingest (I do), na == nb == 1, so cosine reduces to a plain dot product — cheaper, and it's why Qdrant's cosine distance on normalized vectors is fast.
